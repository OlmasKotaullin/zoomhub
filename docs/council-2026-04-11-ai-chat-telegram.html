Консенсус (все 4 эксперта согласны)

1. Сменить LLM-провайдер чата на Gemini 2.5 Flash
GigaChat (12K контекст, слабейшая модель) → Gemini (900K контекст, бесплатно, 1500 RPD). Тот же провайдер что для суммаризации — проверено качество. Fallback: Groq → Claude → GigaChat.
CPO ✓ CTO ✓ Growth ✓ UX ✓
2. Добавить fallback-цепочку в chat_engine.py
Сейчас один провайдер, при ошибке → «Ошибка AI». В summarizer.py уже есть fallback chain — скопировать подход. Gemini → Groq → Claude → GigaChat.
CPO ✓ CTO ✓ Growth ✓ UX ✓
3. Шаблоны-кнопки вместо текстовых примеров
При входе в AI-чат: inline-кнопки [📋 Протокол] [✅ Задачи] [📝 Резюме]. Один тап → готовый ответ. Снижает трение до нуля. Шаблоны уже есть на сайте — перенести в Telegram.
CPO ✓ CTO ✓ Growth ✓ UX ✓
4. Качество важнее количества фич
AI-чат — единственный дифференциатор от Буквицы. Если ответы «глупые» — вся стратегия рушится. Сначала сделать 3 шаблона wow-качества, потом расширять.
CPO ✓ CTO ✓ Growth ✓ UX ✓
5. Сохранить chat_state в БД
In-memory dict теряется при рестарте Fly.io. Юзер пишет вопрос → получает «отправьте аудио». Решение: поле current_chat_meeting_id в таблице User. 30 мин работы.
CPO ✓ CTO ✓ UX ✓
6. Отдельный system prompt для Telegram
Текущий промпт использует ### заголовки и - [ ] чеклисты — Telegram их не рендерит. Нужен Telegram-специфичный prompt: *жирный*, списки через •, ✅ для задач, лимит 2000 символов.
CPO ✓ CTO ✓ UX ✓

CPO (Продуктолог)
User flow, позиционирование, приоритизация

Позиционирование AI-чата

Не «AI-чат», а «Задать вопрос по встрече». Кнопку переименовать с «AI-чат» на «Спросить по записи». Юзер думает действиями, не метафорами.

Критические фичи для 70% «только-бот» юзеров

  • /meetings — список последних записей (нельзя вернуться к старой)
  • /plan — остаток лимита (узнаёт только при отказе)
  • Шаблоны-кнопки — один тап вместо набора текста
  • /chat — быстрый вход в чат по последней записи

Диагностика «глупости»: 60% модель, 25% промпт, 15% контекст

GigaChat (не Pro, не Max) — слабейшая версия. Контекст 12K — обрезка 50%+. Промпт не различает типы вопросов. Для суммаризации Gemini — для чата GigaChat. Несогласованность.

CTO (Техдиректор)
LLM-стек, архитектура, стоимость

Оптимальная fallback-цепочка

Gemini 2.5 Flash (900K, бесплатно) → Groq Llama 3.3 70B (128K, бесплатно, <1с) → Claude Sonnet 4 (200K, $3/1M) → GigaChat (12K, fallback)

Математика контекста

Средний транскрипт 40K символов ≈ 10K токенов + system prompt + история = 13K. GigaChat (12K лимит) — единственный провайдер, который физически не может обработать стандартный транскрипт. Обрезка отрезает конец — где решения и задачи.

Конкретные файлы для изменения

  • chat_engine.py — fallback-цепочка + Telegram prompt + убрать жёсткую обрезку
  • telegram_bot.py — передавать is_telegram=True

Head of Growth
Монетизация, отстройка от Буквицы, виральность

Контринтуитивный вывод: AI-чат сейчас — unfulfilled promise

Технически реализован. Но при «глупых» ответах — это не killer feature, а точка разочарования. B2B-руководители не будут задавать свободные вопросы. Они будут нажимать шаблоны: «Задачи», «Протокол», «Follow Up». Фокус на 3 шаблона wow-качества.

Отстройка от Буквицы

Не «ZoomHub = Буквица + AI-мозг» (делает Буквицу якорем). А «ZoomHub = автопилот для рабочих встреч». Буквица → «не потерять слова». ZoomHub → «не потерять решения».

Виральная петля: публичные протоколы

Юзер нажимает «Протокол» → получает красивую веб-страницу zoomhub.ru/p/abc123 → отправляет в рабочий чат. 3-5 участников видят бренд → 0.5-1 регистрация. При 10 протоколах/день = 5-10 органических регистраций.

Retention: кросс-встречная память

Самый мощный механизм. «За последний месяц у вас 3 встречи про поставщика — вот эволюция обсуждения». Чем больше встреч → тем умнее AI → тем сложнее уйти. Retention +20% на 6-м месяце.

UX-исследователь
Cognitive load, confusion points, Telegram patterns

Когнитивная нагрузка: 5 ментальных моделей (норма 2-3)

Юзер должен держать в голове: «я в чате или нет?», «голосовое vs файл», «state потерян?», «как выйти?», «почему обрезано?». Для ЦА (нетехнари 35-50 лет) — перегруз.

Главная UX-ловушка: случайный выход из чата

Аудиофайл (через скрепку) в chat mode → автоматический выход + новая транскрипция. Без предупреждения. Рекомендация: защитный перехват с вопросом «Что сделать? [Новая транскрипция] [Остаться в чате]».

Reply keyboard как индикатор режима

В Telegram нет строки состояния. Reply keyboard (кнопки вместо клавиатуры) — визуальный индикатор: [📋 Протокол] [✅ Задачи] [📝 Резюме] [❌ Выйти]. Юзер видит кнопки = понимает, что «в чате».

12 рекомендаций, приоритизированы P0-P3

  • P1 Шаблоны-кнопки, короткий onboarding, нумерация чанков, typing loop
  • P2 Reply keyboard, предупреждение об обрезке, контекстные примеры, /meetings
